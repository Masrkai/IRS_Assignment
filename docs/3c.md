## 1. Technical tasks

### 1.1 Build the clustering features (Tasks 1–2)
- Compute, from **training observations only** (the 80% split, seed 425), for each eligible user *u*:
  - r̄ᵤ, the mean rating
  - log(1 + nᵤ), where nᵤ is the number of ratings
  - sᵤ, the rating standard deviation
- Form **Xᵤ = [r̄ᵤ, log(1 + nᵤ), sᵤ]**.
- Z-score each dimension **independently**: zᵤ = (value − μ) / σ, with μ and σ computed on the training data. Use the population σ (divide by N), as in the assignment formula.
- Save the standardization parameters (μ, σ per feature).
- Handle users with undefined sᵤ (for example, a single rating) explicitly and document how.

### 1.2 Run K-means (Tasks 3–4)
- Run K-means for **K ∈ {5, 10, 15, 20, 30, 50}** with seed 425.
- For each K, record:
  - WCSS (inertia)
  - Silhouette score. If the full computation is impractical, use a **reproducible sample** (fixed seed) and state this.
  - Number of users in each cluster (cluster-size table)
- Save the cluster assignments per K, because teammates need them.
  - Member 2 uses them in Section 3 Part 2 (missing neighbors).
  - The whole group uses them in Parts 3–4 (complexity, final decision).

### 1.3 Select and characterize clusters (Tasks 5–7)
- Plot the **elbow curve** (WCSS vs. K) and the **silhouette score vs. K**.
- Choose a configuration using both criteria. **Explain any disagreement** between them.
- Characterize the chosen clusters by rating behavior (mean, std) and activity (number of ratings), for example with a profile table or plot.

### 1.4 Clustering-based CF (Tasks 8–10)
- Apply **mean-centered cosine user-based CF within each cluster** (neighbors come only from the target user's cluster).
- Compare against **global user-based CF** using the **same** similarity measure, discount threshold (β), and neighborhood size (k). These come from the best configuration found in Section 2 Part 1.
- Use the same fixed test set and the same 30 target users.
- Record **MAE, RMSE, coverage, and computational cost** (similarity comparisons and runtime).

## 3. Rules you must follow (apply to your work)

- **Clustering features and standardization parameters come from training data only.** Using test data is a violation.
- **Never treat missing ratings as zero.** Handle zero-variance vectors, insufficient co-ratings, zero denominators, and missing predictions explicitly.
- **Report MAE and RMSE only on successfully predicted ratings**, and report **coverage separately**.
  - Don't rank methods with different coverage by MAE/RMSE alone.
  - Distinguish comparisons on **common test pairs** from comparisons on each method's full predicted subset.
- **Neighborhood size k is a maximum**, not a guaranteed count. Only neighbors with usable evidence may contribute.
- **Theoretical pair-count reduction ≠ measured runtime speedup.** Report both separately.
- State the **exact equations** used, including whether centering uses the user's full training history or only common ratings, and keep that convention consistent.
- Implement K-means and CF math yourself. Libraries are allowed for data handling, plotting, and supporting operations, but not to replace core algorithms unless authorized.
- Use **seed 425** and keep full numerical precision internally (round to 2 decimals for display only).
- Write all code in **Python in VS Code** (no Jupyter or Colab).
